# Cache aufräumen (P6)

**Problem:** `public/sw.js` legte alles in `handschrift-v1` und löschte nie etwas. Mit jedem Deploy kamen neue Hash-Dateien dazu; bei knappem Speicher räumt Safari die ganze Website-Herkunft, auch die Handschriften in IndexedDB.

**Jetzt:** ein Cache pro Build.
- `vite.config.ts` (Plugin `sw-build-id`) ersetzt im gebauten `dist/sw.js` den Platzhalter `__BUILD__` durch einen Hash der gebauten `index.html` (ändert sich, sobald sich eine Hash-Datei ändert). Cache-Name: `handschrift-<hash>`. Gleicher Build = gleicher Name.
- `install`: lädt `./` und alle Dateien, die `index.html` nennt (JS, CSS, Icons, Manifest), in den neuen Cache und übernimmt sofort (`skipWaiting`). Schlägt das fehl (offline), wird trotzdem installiert.
- `activate`: löscht alle Caches mit anderem Namen (auch das alte `handschrift-v1`), dann `clients.claim()`.
- Unverändert: Netz zuerst, Cache als Rückfall; Navigationen mit `cache: 'no-cache'`, ein Update zeigt sich beim nächsten Start.

**Geprüft** (Chrome headless über CDP, `vite preview`, zwei Builds mit verschiedenem Inhalt):
- Build 1 laden: ein Cache `handschrift-5178cca6af` (Seite, JS, CSS, Icons, Manifest).
- Build 2 bauen, neu laden: kurz zwei Caches, ab dem zweiten Laden nur noch `handschrift-1a076ac9e4` mit den neuen Dateien.
- Netzwerk offline, Seite neu laden: App startet aus dem Cache, Oberfläche da.
- Im eingebauten Browser der Claude-App lassen sich Service Worker nicht registrieren; deshalb Chrome.

**Grenze:** Dateien, die nur zur Laufzeit nachgeladen werden (z. B. pdf.js beim PDF-Import), liegen erst nach dem ersten Online-Gebrauch im Cache der neuen Version. Nach einem Update müssen sie einmal online neu geladen werden. Wer das ändern will: Dateiliste des Builds in `sw.js` einbauen (Kommentar `shortcut:`).
